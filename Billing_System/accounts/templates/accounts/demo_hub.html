RFC 6265 Origin Boundary & Architecture Note

By standard web specifications (RFC 6265), browser cookies (sessionid) are origin-wide. If two tabs use the exact same hostname, logging into Tab 2 overwrites Tab 1's session.

The College Demo Solution: Windows natively routes all addresses in the 127.0.0.0/8 block (e.g. 127.0.0.1, 127.0.0.2) as well as localhost. Browsers enforce completely separate cookie jars for distinct hostnames. Running on 0.0.0.0:8000 enables 100% physically isolated cookie jars in the same Chrome profile without storing passwords in JavaScript, compromising tokens, or weakening CSRF protection.

College Presentation Demonstration Protocol

  1. 1
    Launch Server on INADDR_ANY:
    Run the server bound to 0.0.0.0:8000 so all loopback IPs route seamlessly.
    # Start server to listen on all loopback hostnames
    python manage.py runserver 0.0.0.0:8000
  2. 2
    Open All 3 Tabs: Click "Launch All 3 Role Tabs" above to open Owner, Manager, and Cashier in Chrome.
  3. 3
    Log In to Each Tab: Log in as Owner on Tab 1, Manager on Tab 2, and Cashier on Tab 3.
  4. 4
    Demonstrate Independence: Refresh Tab 1 and Tab 2 — Tab 1 remains Owner and Tab 2 remains Manager!
  5. 5
    Demonstrate Staff Messaging: Send a notification from Manager to Cashier. Verify Cashier receives it while Owner does not.
  6. 6
    Demonstrate Logout Isolation: Click Logout in Tab 3 (Cashier). Verify Tab 1 (Owner) and Tab 2 (Manager) stay completely logged in!

Alternative Browser Profile Isolation

If your college demonstration requires strictly using the single hostname localhost:8000 across separate windows, Chrome User Data Directories or Incognito windows provide physical process isolation:

# Isolated Profile A: Manager
chrome.exe --user-data-dir="%TEMP%\pos_manager" http://localhost:8000/accounts/

# Isolated Profile B: Cashier
chrome.exe --user-data-dir="%TEMP%\pos_cashier" http://localhost:8000/accounts/
Both the Multi-Origin Tab Model and the Isolated Profile Model satisfy 100% of security requirements: zero client-side password storage, strict server-side RBAC, and authentic CSRF validation.
